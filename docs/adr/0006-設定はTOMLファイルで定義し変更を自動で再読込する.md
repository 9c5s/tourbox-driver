# ADR-0006: 設定は TOML ファイルで定義し、変更を自動で再読込する

- 状態: 承認 (2026-09-23、Discord で承認)
- 日付: 2026-09-23

## 文脈

ボタンやダイヤルと MIDI メッセージの対応付け、ハプティクスの既定値、MIDI ポート名、接続方式を設定する手段が必要である。
GUI は対象外にした (ADR-0001)。
ユーザーは設定を編集したときに再起動なしで反映されることを求めた。

## 決定

設定は TOML の 1 ファイルで定義する。
パスは `--config` で指定し、省略時は OS の設定ディレクトリを使う。
notify で設定ファイルの親ディレクトリを監視し、300 ms のデバウンスの後に読み直す。
検証に失敗した内容は反映せず、前の設定を維持してログに出す。
反映は、押下中のボタンの解放、マッピングの差し替え、ハプティクスの作り直し、ポートの開き直し、デバイスの再接続の順で行う。

## 検討した選択肢

- GUI で設定する。使い勝手はよいが GUI の工数が大きく、最初の動くものが出るまでが遠い。
- 設定を固定してまず動かす。実用にするには結局設定手段が要る。
- 再読込は行わず再起動で反映する。ユーザーの要望に合わない。

## 結果

- 起動時の設定エラーは終了し、再読込時のエラーは前の設定を維持する、という非対称な扱いになる。
- 保存途中の内容でも検証に通れば反映される。ファイルを置換して保存するエディタなら途中の内容は読まれない (設計書 5.4 節)。
- 再読込は、Windows の MIDI 入力ポートを開き直す復旧手段も兼ねる (設計書 6.2 節)。
