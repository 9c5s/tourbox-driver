# ADR-0007: 修飾ボタンは押している間だけ有効なレイヤとし、同時に 1 つだけにする

- 状態: 承認 (2026-09-23、Discord で承認)
- 日付: 2026-09-23

## 文脈

TourBox の特徴は「ボタンを押しながら回す、押す」の組み合わせ操作で、少ないコントロールで多くのパラメータを扱える。
デバイスは同時押しに専用コードを持たず、各コントロールの押下と解放を独立に送るだけである。
ハプティクスの設定もデバイス側では「修飾 1 つと軸」までしか区別しない。
既存の非公式ドライバ (tuxbox、jasonrohrer) はどちらも、同時に有効な修飾を 1 つ (先に押した方) に限定している。

## 決定

設定ファイルの `[map.with.<ボタン>]` で定義されたボタンを修飾ボタンとし、押している間だけそのレイヤの割り当てを使う。
レイヤに定義がない操作は基本レイヤにフォールバックする。
同時に有効な修飾は先に押した 1 つだけで、修飾中に押した別の修飾ボタンは通常ボタンとして扱い、先の修飾を離しても昇格しない。
修飾ボタン自身の Note や CC は通常どおり送る。
修飾の解釈はライブラリではなく MIDI アプリの engine が担う。

## 検討した選択肢

- 組み合わせを区別せず、各ボタンと回転操作が常に同じメッセージを送る。実装は最小だが、DAW 側で組み合わせを解釈することはほぼできず、コントロール数が不足する。
- 複数の修飾の同時押しを許す。デバイスのハプティクスが区別できず、既存ドライバにも前例がなく、設定の組み合わせが増えるため採らない。

## 結果

- 押下時に送ったメッセージを engine が記憶し、解放時はその記憶に対応する Off を送る。レイヤの切替中に押下と解放で割り当てが変わっても Note On が残らない (設計書 5.3 節)。
- 絶対 CC の内部値は「レイヤ × 操作」ごとに独立に持つ。
