# ADR-0011: プロトコルは公開解析を参照し、ライセンス未指定の実装からコードを流用しない

- 状態: 承認 (2026-09-23)
- 日付: 2026-09-23

## 文脈

TourBox Elite のプロトコルは、Linux 向けの非公式ドライバ 3 つで解析済みである。
AndyCappDev/tuxbox (Python) と rowan-mcalpin/TourBoxForLinux は MIT で、jasonrohrer/tourBoxEliteLinuxDriver (C89) はライセンスが指定されていない。
3 つは系譜関係にあり、USB と BLE のアプリケーション層のメッセージ (アンロック 8 バイト、設定 94 バイト、イベント 1 バイト) は一致している。
本プロジェクトは Rust で書くため (ADR-0002)、いずれのコードもそのままは使えない。
実機の USB キャプチャ (ADR-0005) で、公開解析のバイト値、オフセット、UUID に相違がないことを確認した。

## 決定

プロトコルの事実 (VID と PID、UUID、アンロック列、イベントのコード表、94 バイトのテンプレートとオフセット表) は公開解析と実機キャプチャに基づいて設計書 2 章に記述し、実装は設計書から書く。
ライセンス未指定のリポジトリは事実の確認にのみ使い、コードは流用しない。
MIT のリポジトリも、コードの転記ではなく設計書の記述を経由する。

## 検討した選択肢

- tuxbox のコードを Rust に移植する。言語が異なるため転記の利点が小さく、tuxbox には未使用の残骸 (STMicro の VID と PID) や実機未確認の定義 (回転停止イベント) も含まれるため、事実を選別して設計書に書く方が安全である。
- 公式コンソールを解析してプロトコルを確定する。保護の回避になるため採らない (ADR-0005)。

## 結果

- 設計書 2 章がプロトコルの唯一の根拠になり、未確認事項 (アンロックのみでイベントが届くか、DTR の要否など) も同じ場所に列挙する。
- 参照元とライセンスは設計書 2 章の冒頭に明記する。
