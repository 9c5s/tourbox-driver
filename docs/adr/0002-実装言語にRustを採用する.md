# ADR-0002: 実装言語に Rust を採用する

- 状態: 承認 (2026-09-23、Discord で承認)
- 日付: 2026-09-23

## 文脈

Windows と macOS の両方で、シリアル (USB CDC ACM)、BLE、MIDI の 3 領域を扱う必要がある。
常駐して動くドライバであり、起動の軽さと配布のしやすさが求められる。
既存の参照実装 (tuxbox) は Python で書かれている。

## 決定

Rust で実装する。
シリアルは serialport、BLE は btleplug、MIDI は midir を使い、非同期基盤は tokio とする。

## 検討した選択肢

- Python (pyserial、bleak、python-rtmidi)。tuxbox のコードを参照しやすいが、配布に PyInstaller などの同梱が要り、常駐アプリとして起動が遅く重い。
- TypeScript (Node または Electron)。serialport と MIDI は問題ないが、BLE ライブラリ (noble 系) の Windows 対応が不安定で、常駐ドライバとしては重い。
- C++ と JUCE。MIDI と GUI は充実しているが、シリアルと BLE は別途ライブラリを探す必要があり工数が増える。

## 結果

- 単一バイナリで配布でき、GUI が必要になれば egui や Tauri を足せる。
- btleplug が非同期 API のため tokio を採用し、serialport の同期読み取りは専用スレッドで実行してチャネルで渡す。
- macOS の BLE では、ターミナルアプリへの Bluetooth 権限付与が必要になる (設計書 4.3 節)。
