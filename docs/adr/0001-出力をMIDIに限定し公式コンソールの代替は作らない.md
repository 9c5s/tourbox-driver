# ADR-0001: 出力を MIDI に限定し、公式コンソールの代替は作らない

- 状態: 承認 (2026-09-23、Discord で承認)
- 日付: 2026-09-23

## 文脈

当初の依頼は「TourBox Elite を公式コンソールアプリに依存せず使える汎用ドライバ」で、Windows と macOS の両対応とハプティクスの対応が条件だった。
用途を確認すると、ユーザーの目的は TourBox を MIDI コントローラーとして使うことであり、キーボードやマウス入力への変換は必要なかった。
MIDI の受け手は特定の DAW に絞らず、何にでも使えることが求められた。
接続方式は USB (CDC ACM) と BLE の両方が普段の利用に含まれる。

## 決定

出力は MIDI のみとし、OS の MIDI 出力ポートに送る汎用設計にする。
MIDI 入力ポートも持ち、DAW からの Control Change でハプティクスを切り替える。
キーボードやマウス入力への変換 (公式コンソールの代替) と GUI は対象外にする。
接続は USB と BLE の両方を最初から対象にする。

## 検討した選択肢

- 公式コンソールの代替として、操作をキーボードやマウス入力に変換する。用途に含まれず、範囲が広がりすぎるため採らない。
- ライブラリ (SDK) だけを作り、MIDI 変換は利用者に任せる。ユーザー自身が MIDI 変換を必要としており、ライブラリの最初の利用者として MIDI アプリを作る方が検証になるため採らない。
- USB だけで始めて BLE を後回しにする。ユーザーが両方を使うため採らない。

## 結果

- 通信ライブラリと MIDI アプリの 2 層に分ける (ADR-0003)。
- 将来キーボード変換などを足す場合も、ライブラリはそのまま使える。
- 受け手を絞らないため、Windows では仮想 MIDI ポートの用意が課題になる (ADR-0004)。
