# ADR-0013: 文書はすべて常体で書き、プログラムの出力は敬体にする

- 状態: 承認 (2026-09-23、Discord で承認)
- 日付: 2026-09-23

## 文脈

設計書、実装計画、ADR、プロトコル資料は常体 (である調) で書かれている。
一方で、開発者の全プロジェクト共通の規約では README を敬体で書くことになっており、このままでは README だけ文体が異なる。
ユーザーは「ドキュメントは全て常体で書く」と指示し、その方針自体を ADR に残すよう求めた。
プログラムの出力 (ログ、エラーメッセージ、CLI のヘルプ) は利用者に向けた文であり、文書とは読まれ方が異なる。

## 決定

README を含む docs 配下の文書と、コード内のコメントはすべて日本語の常体で書く。
プログラムの出力 (ログ、エラーメッセージ、CLI のヘルプ、CI の通知) は敬体で書く。
文書の文体は、日本語の技術文書の規範 (一文一行、ダッシュと中黒を使わない、擬人化と口語を避ける) に従う。

## 検討した選択肢

- README だけ敬体にする。共通規約には沿うが、同じリポジトリの中で文書の文体が混在する。
- プログラムの出力も常体にする。文書と出力の文体は独立に決められ、出力は利用者への案内なので敬体を残す方が読み手に合う。

## 結果

- 実装計画の共通制約に同じ規則を書き、README を書くタスク (Task 1、Task 14) はこれに従う。
- ADR の形式検査 (ADR-0012) の出力は敬体のままでよい。
