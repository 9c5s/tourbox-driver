# ADR-0021: Windows の MIDI 出力ポートの定期的な開き直しを取りやめる

- 状態: 提案
- 日付: 2026-09-25

## 文脈

ADR-0020 は、WinRT の出力ポートの接続が開いてから約 2 時間でエラーなしに無効になるという実験結果に基づき、`Existing` の出力ポートを 60 分ごとに開き直すと決めた。
この決定は b0cbf03 と f3fcfd6 で実装した。

2026-09-25 に、その実験結果が実験ツールの不具合によるものだと分かった (詳細は ADR-0020 の結果にある)。

- 実験ツールは 128 以上の値を CC のデータバイトとして送っていた。そうした送信は WinRT ではエラーにならず、受信側に届かない。
- 値を 127 以下にした送信は、開いたままの 12.3 時間 (10 分ごと)、60 分ごとの開き直し、5 分ごとの Active Sensing のいずれでも全件が届いた。
- 発端の常駐アプリの事象は、loopMIDI の再起動より前に WinMM で開いた受信側が古い接続のまま残っていたためで、常駐アプリの出力は届いていた。
- 本アプリが送る Note と CC のデータバイトは、設定の検証と engine の飽和により常に 127 以下である。

したがって、定期的な開き直しで防ぐべき事象は確認されていない。

## 決定

ADR-0020 の定期的な開き直しを取りやめる。
出力ポートは ADR-0018 のとおり、一覧から消えたときだけ閉じて開き直す。
b0cbf03 と f3fcfd6 の変更 (`OutputState` の時刻の注入、`REOPEN_INTERVAL`、関連するテスト、設計書 6.1 節と README の該当箇所) を取り除く。
ADR-0020 の状態を「置換 (ADR-0021 による)」にする。

## 検討した選択肢

- 予防として残す。開き直しは 16 ms で終わり害は小さい。しかし根拠のない仕組みが時刻の注入とテスト 6 件を残し、将来の原因調査で誤った手がかりになる。
- 間隔を延ばして残す。上と同じく根拠がない。

## 結果

- 出力ポートの扱いは ADR-0018 の実装に戻り、`OutputState::new` の引数も元に戻る。
- 長時間の常駐で出力が届かない事象が再び見つかった場合は、先に受信側が loopMIDI の再起動より前から開いたままでないかを確かめる。そのうえで原因が本アプリにあれば、新しい ADR を書く。
