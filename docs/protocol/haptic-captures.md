# ハプティクス設定メッセージの実機キャプチャ

取得日: 2026-09-23
取得方法: Windows 10 上で公式 TourBox Console 5.11.3 と TourBox Elite (USB、VID 0xC251 / PID 0x2005) の間の USB バルク転送を USBPcap 1.5.4.0 で記録し、tshark でホストからデバイスへの OUT ペイロードを抽出した。
用途: `crates/tourbox` の protocol テストで、94 バイトメッセージの組み立て (`HapticConfig::encode`) の期待値として使う。

すべて 94 バイトで、ヘッダ `b5 00 5d`、(ID、値) の 45 組、終端 `fe` の構造である。
値バイトは強度 (なし `0x00`、弱 `0x04`、強 `0x08`) と速度 (速い `0x00`、中速 `0x01`、遅い `0x02`) の和である。

## 固定テンプレート (全値 0)

ID バイトの並びは次のとおり。値バイトはすべて `00` で示す。

```
b5 00 5d 04 00 05 00 06 00 07 00 08 00 09 00 0b 00 0c 00 0d 00
0e 00 0f 00 26 00 27 00 28 00 29 00 3b 00 3c 00 3d 00 3e 00
3f 00 40 00 41 00 42 00 43 00 44 00 45 00 46 00 47 00 48 00
49 00 4a 00 4b 00 4c 00 4d 00 4e 00 4f 00 50 00 51 00 52 00
53 00 54 00 a8 00 a9 00 aa 00 ab 00 fe
```

## キャプチャ 1: 全軸「強、中速」(公式コンソールの既定状態)

コンソールの状態: ノブ、スクロール、ダイヤルすべて「触覚: 強」「回転速度: 中速」、触覚フィードバック作動 ON。

```
b5005d0409050906090708080809090b080c090d090e080f0826092709280929093b093c093d093e093f0940094109420943094409450946094709480949094a094b084c084d084e084f0850085108520853085408a808a908aa08ab08fe
```

備考: 値は一様ではない。オフセット表 (設計書 2.4 節) で読むと、Knob は Top と Side との組み合わせだけ `08` (強、速い) で他は `09` (強、中速)、Scroll は Tall と Side との組み合わせだけ `08` で他は `09`、Dial は全組み合わせ `08` である。UI の表示は 3 軸とも「強」「中速」だったので、表示と一致しない組み合わせ (Top+Knob、Side+Knob、Tall+Scroll、Side+Scroll、Dial 全部) はプリセット側で個別に設定された値と推定する。本ドライバの既定値 (全組み合わせ「強、中速」) はこのキャプチャと同一ではない。

## キャプチャ 2: ノブだけ「強、速い」

コンソールの操作: ノブの回転速度を「速い」に変更。

```
b5005d0408050906080708080809090b080c090d090e080f0826092709280929093b083c083d083e083f0840084108420843084408450946094709480949094a094b084c084d084e084f0850085108520853085408a808a908aa08ab08fe
```

備考: キャプチャ 1 との差分は 12 か所で、オフセット 4 (Knob 単体) と 8、34、36、38、40、42、44、46、48、50、52 (Short、Knob 押込、Scroll 押込、Dial 押込、Tour、上、下、左、右、C1、C2 との組み合わせ) が `08` に変わった。Tall (6)、Top (10)、Side (12) との組み合わせは変わらなかった。キャプチャ 3〜5 も同じ 12 か所だけが変わる。UI の軸単位の変更は全組み合わせではなく、プリセットで個別に設定されていないと推定される組み合わせにだけ及ぶ。

## キャプチャ 6: 触覚フィードバック作動 OFF (全軸なし)

コンソールの操作: 左下「触覚フィードバック作動」を OFF。

```
b5005d0401050106000700080009010b000c000d000e000f0026002700280029003b003c003d003e003f0040004100420043004400450046004700480049004a004b004c004d004e004f0050005100520053005400a800a900aa00ab00fe
```

備考: 強度はすべてなし (`0x00`) だが、ID `04` (Knob 単体)、`05` (Tall+Knob)、`09` (Scroll 単体) の値は `01` (速度: 中速) である。作動 OFF でも速度ビットは一部残る。本ドライバの master OFF は速度も含めて全値 0 を送る設計であり、公式と同一ではない。

## 観測されたホストの振る舞い

- 操作中にホストが送ったメッセージは 30 件すべてが上記と同じ構造の 94 バイトで、他の種類のメッセージはなかった。
- 公式コンソールの UI は軸単位の設定で、ノブの設定を変えると 12 の組み合わせ (単体と、Tall、Top、Side 以外の修飾との組み合わせ) が同時に書き換わった。Tall、Top、Side との組み合わせは変わらなかった。プリセットで個別に設定されている組み合わせは軸単位の変更から除外されると推定するが、UI 上で確認はしていない。
- アクティブウィンドウの切り替えでプリセットが自動切替され、そのたびに 94 バイト全体が再送された。
- USB と BLE が同時に接続されている状態で、公式コンソールは USB 側だけを使った。
